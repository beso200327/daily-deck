# Habit creation, contextual quotas and Done exits

All creation entry points use the same existing save transaction: Today/Progress header, Habits header/tile, empty-deck action and one-time task manager (after selecting Recurring habit). A new habit scheduled for the save date produces exactly one occurrence, prepended persistently without changing older records or relative order. It uses the same creation entrance, highlight, sidebar reveal and shared counters/preview as one-time tasks. Excluded weekdays create only a habit definition; editing never invokes creation feedback or changes order. The occurrence-generation and plan-limit models are unchanged.

The form no longer shows two quota pills. Its sticky footer shows one muted line for the selected type only: `n of 10 active tasks` or `n of 5 habits`. Pro hides the entire block. At capacity, new-item forms explain that type's allowance and offer Upgrade; existing-item editing remains available without a creation-block message. Save still uses the existing authoritative transaction capacity check. Switching types immediately switches the quota context, so a full habit allowance does not imply tasks are blocked. Upgrade opens a second modal while retaining the editor, text, schedule and photo draft. Its allowance line also refers only to the selected type. Checkout remains the existing prototype/preview flow; no live billing is introduced.

Done previously targeted well beyond the viewport with a quick easing, allowing the card to leave sight early. The new 320 ms keyframe exit captures the article's computed transform at release, then moves from that exact matrix just past the right screen edge with a slight rotation and smoother easing. The keyed card stays mounted and opaque throughout, above the real next card as that card promotes. Animation completion releases the existing transaction; only a successful persisted completion updates counts/history and removes the node. The existing guarded fallback covers missing animation events. Buttons, mouse gestures, touch gestures and widget-preview actions share this action sequence. The final card exits before the empty state appears. Reduced motion uses a 90 ms fade at the release position. Done toasts remain absent; history, timestamps and Undo retain their existing model semantics.

Tests cover selected/excluded weekdays through all six entry points, repeated Save clicks, identity and old-order preservation, reload, contextual task/habit limits, draft-preserving Upgrade, Pro suppression and editing at capacity. Done browser tests inspect actual CSS-animation frames at 0/80/180/319 ms for mounted identity, full opacity, exact start, rightward movement, offscreen endpoint and no premature write/empty state. They exercise button/mouse/touch input, one/three-card decks, next real content, duplicate prevention, one completion event, Undo/reload and reduced-motion fade. Touch samples wait for the final move frame before comparing transforms.

See web VALIDATION.md for final results. Native iOS code is unchanged. Chromium desktop and iPhone-sized touch emulation do not verify real Safari/PWA compositor timing or VoiceOver. Native widget execution requires Xcode and an iPhone/simulator. No manual deployment; pushing main can trigger existing Vercel automation.
