# Daily Deck launch-readiness audit

Checked **2026-11-05** (owner timezone Asia/Tbilisi). **NOT a launch approval or legal certification.** This is an engineering audit of the repository plus explicitly limited runtime evidence. Native iOS execution, production hosting settings, current official legal/platform text, and owner decisions remain blockers.

## Owner decisions recorded

- Operator is based in **Georgia**. Exact legal entity/controller identity and public support/privacy contact: owner asked to skip for now; remain unresolved, not invented.
- Intended markets: **Georgia, Europe, UK, USA**. “Europe” is not a legal jurisdiction; EU/EEA and non-EEA countries need an explicit list. State-specific US obligations may also apply.
- Mainly adults, potentially **14–15+**. Minimum eligibility, actual audience, child-access assessment and market-specific consent rules remain unresolved. No universal age threshold, date-of-birth collection or age gate has been introduced.
- Proposed **USD 3.99/month** subscription unlocks unlimited use. Original wording mixed “first ten habits and tasks” with “6 habits 10 daily tasks.” This earlier proposal was superseded by the later explicit request: **10 active incomplete one-time tasks plus 5 active habit definitions**, not a daily creation quota. A browser-local gate and isolated preview-only simulations now implement that prototype policy. Treatment of completed/archived tasks, resets, existing users, tax/local pricing, web/native storefronts, entitlement restoration and identity is unresolved.
- The shipped source remains free, local-only, accountless, without purchases, advertising or analytics. There is now a prototype capacity gate, but no live paywall/checkout or trusted paid entitlement; billing is not ready. Accounts are unnecessary for today's product; future subscriptions require a separate purchase/restore/security design, not arbitrary registration fields.

## Implemented safeguards in this audit

1. Accessible local backup/export, schema-validated non-destructive import and confirmed full web-data deletion in the existing About dialog. Exports include photo/history versions; imports reject conflicting edits or malformed relations/events/pixels, are idempotent for matching backups, and roll back newly added images if the deck write fails. No unrelated origin storage is cleared.
2. Retain metadata-free oriented source pixels for **new** photo selections and reuse them for future crops. Crop processing prefers bitmap/offscreen APIs with an HTML image/canvas fallback; draft visual URLs update before paint. Existing saved sources/photos/history are untouched. Exports warn about private contents, unencrypted files, OS-synced Downloads and legacy metadata.
3. Disable consent-based PWA reload while **any app modal**, including data controls, is open; no permission prompts or account/payment features added.
4. Remove unused Vercel CLI and patch the existing Vite/Vitest major versions to resolve reported development advisories. Keep static Git-based Vercel import configuration.
5. Add production CSP configuration and verify it in a production-browser harness; actual hosted headers remain an owner check.
6. Add a minimal explicit native privacy baseline resource to both target bundles and validate project wiring. Native SwiftUI/core/widget behavior is preserved; archive/SDK declarations still require current Apple and Xcode review.
7. Add development-only legal drafts, data/asset inventory, release/incident/rollback runbook. No incomplete legal draft is served from `apps/web/public` or presented as approved policy.
